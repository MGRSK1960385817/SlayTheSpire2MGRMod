## 20260817-01 ✅

日期：20260817。

类型：BUG 修复。

修改内容：SL 保存并重进战斗后，“时间线之东”此前永久增加的音符生成数量会恢复为基础值。

## 20260818-02 ✅

日期：20260818。

类型：BUG 修复与音频表现改进。

修改内容：有玩家在人物选择界面把光标移到 MGR 人物并点击后，游戏会立即失去响应，严重时直接闪退。从玩家的视频看，卡住发生在人物选择音效真正播放之前：界面没有继续加载人物图片和背景，也没有听到任何选择音效。最初收到的日志片段只包含 RitsuLib 反射枚举警告、公共资源预加载和窗口焦点变化，缺少真正的异常堆栈，因此无法只凭这段日志证明是图片、背景或人物数据导致的问题。

后续还发现了几项与同一套音频流程有关的表现问题：人物选择音效虽然能够播放，但音量明显偏小；音符、和弦、书写声和故障声在部分场景中几乎听不到；两张能力牌所使用的书写声和故障声只播放一次，没有按预期持续循环。这些现象并非同一个错误，但都来自 MGR 自定义音频从原始文件播放迁移到 FMOD Studio 事件播放的过程中，因此统一进行了排查和修复。

为什么会出现错误：

1. 旧实现把角色选择音效作为 OGG 资源交给 RitsuLib 的 `AudioSource.ResourceFile`、`StreamingResourceMusic` 和底层 `load_file_as_sound` 流程处理。人物选择发生在界面切换的关键路径上，如果原始音频文件的解析、流式加载或声音对象创建长时间不返回，主线程就无法继续执行后续人物图片、背景和界面状态更新。玩家看到的结果便是“点击人物后整个游戏定住”，而且因为调用尚未返回，连音效本身也不会响。这种故障未必会立即产生一条清晰的托管异常，所以残缺日志中可能只留下卡死前最后完成的普通初始化信息。

2. 旧的五个 OGG 文件经过资源导入、运行时文件读取和声音对象创建后才进入播放流程，角色选择音效又位于对卡顿极其敏感的 UI 操作中。即使音频内容本身没有损坏，这条运行时加载链也比直接播放已经构建好的 FMOD 事件多出若干可能阻塞或失败的环节。为了消除这一类不可控因素，正式方案不再尝试给 `load_file_as_sound` 增加等待或超时补丁，而是移除了 MGR 运行时对原始 OGG 加载链的依赖。

3. 音频迁移到 FMOD Bank 后，最初仍沿用了旧的原始文件播放音量，例如音符、和弦和循环音效原先使用的较小倍率。FMOD Studio 事件会经过事件自身、Bus 和游戏总线的音量共同处理，旧倍率直接套用后会造成二次衰减，因此出现了“事件已经成功启动，但实际听起来像没有播放”的情况。对源音频响度的检查也表明，音符、和弦、书写声和故障声本身的平均响度低于人物选择音效，需要分别补偿，而不能只提高整个游戏的音量。

4. 循环音效还包含两个独立问题。首先，RitsuLib 的循环播放选项默认认为事件中存在一个名为 `loop` 的 FMOD 参数，并会在启动时设置该参数；MGR 的自定义事件没有这个参数，所以日志出现了无法设置 `loop` 参数的错误。其次，保留一个 FMOD 事件实例只代表它可以在以后被停止和释放，并不会自动让事件时间轴从结尾回到开头。原先的 Writing 和 Glitch 事件只是普通的单次声音，时间轴中没有 Loop Region，因此即使成功取得播放句柄也只会播放一次。

5. `.bank` 和 `GUIDs.txt` 不属于 Godot 通常自动导入的资源类型。如果脚本打包时没有继承项目导出预设中的非资源文件过滤规则，开发目录中存在这些文件也没有意义，最终 PCK 仍可能缺少 Bank 或 GUID 映射。这样代码里的事件路径就无法在玩家环境中正确解析，因此必须把打包规则也视为修复的一部分，而不只是修改播放代码。

最终修复方式：

1. 将全部五个 MGR 音频制作并构建到 `MGR.bank`，同时随 Mod 提供对应的 `GUIDs.txt`。目前使用的事件分别为 `event:/MGR/sfx/MGR_charselect`、`event:/MGR/sfx/NoteChannel`、`event:/MGR/sfx/Chord`、`event:/MGR/sfx/Writing` 和 `event:/MGR/sfx/Glitch`。Mod 初始化时通过 RitsuLib 提供的 FMOD Studio Bank 延迟注册和 GUID 映射注册接口加载它们，业务代码只负责按事件路径播放，不再临时把 OGG 转换成声音对象。

2. 人物选择音效改为直接写入 `CharacterAudioAssetSet` 的 FMOD 事件路径，并由游戏原有的 `SfxCmd.Play` 流程播放。原先专门把人物选择音效重定向到 ResourceFile 的补丁已经移除。这样点击 MGR 时执行的是与原版人物选择音效同类的事件调用，图片和背景加载不再等待 MGR 原始音频文件的同步处理。

3. 音符和和弦等一次性音效统一改为 `SfxCmd.Play(eventPath, volume)`；书写声和故障声仍保留可停止、可释放的 `IAudioHandle` 生命周期，以便能力结束或界面租约释放时及时停止。自定义循环事件明确设置 `UsesLoopParameter = false`，避免再向不存在的 `loop` 参数写值。

4. 在 FMOD 工程中为 Writing 和 Glitch 事件的实际声音时长添加 Loop Region，使循环行为由 Bank 内的事件时间轴正确定义。Writing 的循环区间覆盖约 12.701 秒，Glitch 的循环区间覆盖约 1.736 秒。重新构建后的 Bank 已替换进 Mod，因此循环句柄负责控制开始和停止，FMOD 事件自身负责从结尾回到开头。以后如果重新打开 FMOD 工程并构建 Bank，必须保留这两个 Loop Region，否则“只播放一次”的问题会重新出现。

5. 为 MGR 事件增加了局部音量倍率逻辑，只匹配 `event:/MGR/` 路径，不会放大原版游戏或其他 Mod 的音效。人物选择音效拥有独立倍率，音符、和弦、书写声和故障声也保留各自的基础倍率；以后可直接在 `MgrAudio` 的集中参数中调整，不必重新编辑每个调用位置。这样既能补偿 Bank 事件与源文件响度的差异，也避免为了一个较安静的 MGR 音效改变全局 Bus。

6. Godot 导出预设中明确包含 `MGRMod/audio/*.bank` 和 `MGRMod/audio/GUIDs.txt`，并对实际导出的 PCK 进行了检查，确认其中 Bank 与 GUID 文件的内容和哈希与构建产物一致。因此，无论使用编辑器导出还是项目脚本调用该导出预设，最终安装包都会携带事件播放所需文件。

7. 排查期间曾在 Bank 注册、GUID 映射、每次准备播放、播放调用返回、循环句柄创建和停止等阶段加入详细诊断日志。它们证明 Bank 已成功注册、五个事件均已映射，并且音符和和弦的播放调用能在极短时间内返回；同时也直接暴露了缺少 `loop` 参数的问题。玩家确认新版本不再因选择 MGR 而崩溃后，这批高频额外日志已经移除，只保留 Bank 注册结果和真正失败时需要的警告，避免长期污染正常日志。

修复解决的问题：人物选择不再经过可能阻塞的 `ResourceFile/load_file_as_sound` 原始文件加载链，已经解决点击 MGR 后无音效、无图片、无背景并卡死或闪退的核心问题；五个音频现在统一由同一套 FMOD Bank 和事件路径管理；较安静的事件可以单独补偿音量；Writing 和 Glitch 具备真正的时间轴循环能力，并且仍能在正确时机停止和释放；导出包也明确包含运行时必需的 Bank 与 GUID 映射。MGR 运行时已经不再直接使用原来的五个 OGG 文件，不过 FMOD 工程 `Assets` 目录中的源 OGG 仍然是以后重新构建 `MGR.bank` 的素材，不能与运行时冗余副本一并误删。

验证结果：Release 配置编译和脚本打包均通过，未产生编译警告或错误；安装目录中的 DLL 与本地构建产物哈希一致，导出 PCK 中的 Bank 和 GUID 映射也已核对。最新实机反馈已经证明人物选择崩溃不再复现。循环事件的代码参数和 Bank 时间轴均已修正，后续如需继续微调，只需要修改集中音量参数或 FMOD 事件内容，不需要恢复旧的 OGG 运行时加载方案。

## 20260818-03 ✅

日期：20260818。

类型：BUG 修复。

修改内容：多人游戏中打出“活动小丑”并与抽牌堆中的诅咒交换位置时，房主以外的玩家可能因牌堆数据不同步而掉线。

原因定位：卡牌通过仅在发起手动打牌的本地客户端执行、且发生在同步 `PlayCardAction` 之前的 `OnEnqueuePlayVfx` 保存原手牌索引，随后又用该非同步索引直接重排真实手牌模型，导致不同客户端得到不同的手牌顺序。

修复与改善：移除展示阶段手牌索引对真实牌序的修改，让诅咒入手顺序完全由原生同步牌堆命令管理，同时保留活动小丑进入诅咒原抽牌堆位置的效果。

## 20260818-04 ✅

日期：20260818。

类型：BUG 预防与表现架构改进。

修改内容：演奏队列此前依靠根节点 `ZIndex = 55`、悬停 `300`、生成牌入队 `320`、离队 `450`、终结演出 `419/420` 以及独立 `CanvasLayer = 90` 保证可见。该方案能让队列高于人物，却也可能在选牌、查看卡牌或其他原版界面打开时继续覆盖在最上方，与已经出现的人物立绘遮挡问题属于同类层级风险。

原因定位：这些层级值把“队列内部谁盖住谁”和“整个队列相对原版 UI 位于哪里”混在同一套全局 Z 排序中。只把根节点从正 Z 改为零仍不够，因为卡牌子节点、悬停大图、入队和离队动画的更高相对 Z 仍可能越过原版 UI；直接删除全部 Z 又会破坏重叠卡牌顺序、悬停置顶、五线谱前后关系和金枪鱼冲锋演出。

修复与改善：将持久队列、命中代理和临时卡面统一迁入原版战斗 UI 的自由定位容器 `MessyCardPreviewContainer`，新增轻量跟随节点，把人物画布变换和队列偏移转换到战斗 UI 坐标，因此队列仍会跟随人物移动、缩放和震动。队列内部拆分为五线谱、卡牌、终结撞击和终结卡影四个固定宿主；普通卡牌通过 `MoveChild` 按机械顺序排列，悬停与离队时临时移动到末尾，状态刷新后重新应用该临时顺序。悬停大图、生成牌入队和真实出牌入队均恢复默认 Z，并显式完成视口到父节点局部坐标的转换；临时 `NCard` 进入和离开 MGR 流程时都会复位对象池层级状态。

界面保护同时补上了 `InspectCardScreen`，并直接订阅卡牌查看与遗物查看界面的可见性变化。选牌 overlay、capstone、地图、卡牌查看或遗物查看出现时，持久队列、透明命中区域和悬停大图会一起隐藏。演奏队列相关代码目前不再使用任何非零 Z 或私有高 CanvasLayer，前后关系完全由原版战斗 UI 分支和节点树顺序决定。

后续扩展：音符栏原先仍保留根节点 `ZIndex = 50`、命中区域 `20`、提示框绝对 `4096` 以及内部负 Z，因此进一步迁入同一套原版战斗 UI 分层。共享宿主固定按“音符栏 → 演奏环境 → 演奏卡牌”绘制，保证二者重叠时演奏堆覆盖音符栏；音符星屑、空槽、音符本体和命中区域则改用槽位树顺序。白虎野之女的持续萤火也移除 `ZIndex = 18` 并进入演奏环境层。完成这些修改后，专门抬高所有提示框和药水弹窗的两个全局补丁已删除，相关 UI 恢复原版层级。

验证结果：已完成非零 Z、旧层级参数、旧 `CanvasLayer` 和对象池复位点的静态检索。此前出现的 `CardLocation` 和伤害修改接口错误，后来确认是项目默认 v0.111 兼容目标与本地正式版 v0.107 游戏程序集不匹配，并非代码基线损坏。明确使用 `Sts2CompatTarget=0.107.1` 后，完整 Release 构建为 0 警告、0 错误，PCK 导出与本地游戏目录安装均已完成；本地构建 DLL 与安装目录 DLL 的 SHA-256 完全一致。作者于 2026-08-19 确认相关实机回归通过，本项已验证并发布。

## 20260818-09 ✅

日期：20260818。

类型：项目架构与开发流程改进。

修改内容：MGR 需要同时支持当前正式版 v0.107.1 和最新测试版 v0.111，但不希望依赖 CVC，也不希望以后为所有过期中间测试版无限累积 DLL。

修复与改善：完成稳定 `MGRMod.Loader`、正式版/测试版两个原生 payload、SHA-256 版本清单、条件编译接口分支、集中反射桥和双版本构建链；保存真实 v0.107.1 原始引用并验证可独立重建。发布策略固定为只滚动保留“当前正式版 + 最新测试版”，同时新增 [`MGR双版本兼容维护手册.md`](../project/MGR双版本兼容维护手册.md)，集中记录发布结构、CVC 取舍、源码分支边界、DLL 归档、未来升级流程和验证基线。
