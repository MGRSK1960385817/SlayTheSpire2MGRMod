# RegentFX 视觉结构吸收实施记录

> 建立日期：2026-08-19。本文记录 MGR 自主实现的视觉结构、接入边界和验证结果；只借鉴动画组织方法，不复制 RegentFX 的贴图、场景、Shader、声音或反编译源码。

## 一、实施目标

本轮把以下结构接入 MGR 已有卡牌：

1. 短寿命、局部作用的屏幕采样扭曲；
2. “向内汇聚—语义转换点—向外释放”的三段式资源转换；
3. “预兆—玩法结算—非阻塞尾迹”的两阶段演出；
4. 常驻或原有主体动画与一次性强调层相互独立。

所有玩法命令仍按原顺序等待；新增尾迹只能非阻塞播放，必要的可读前摇必须进入统一视觉等待并服从演奏加速。

## 二、当前实施批次

| 对象 | 当前表现 | 本轮目标 | 约束 |
|---|---|---|---|
| 极彩色 | 棱柱施放环和彩虹星环 | 在星环下增加一次轻量局部棱镜扭曲 | 每次和弦最多一个实例，不逐音符生成 |
| 银河灯 | 直接移除全部音符，再逐个生成星空音符 | 旧音符整体汇聚，转换点脉冲，随后沿用现有星空音符生成 | 不复制或临时修改真实音符节点，不改变生成顺序 |
| 陨星余波 | 紫色横向风线与暗角 | 先向角色汇聚，再向外释放陨星余波 | 能量、抽牌、债务命令顺序不变 |
| 「 鳥 」 | 鸟影与大型金色陨星同步坠落 | 仅增加很短的高空预兆或路径强调 | 不延长死亡后的音符尾部，不增加全屏遮挡 |
| 立方棱镜 | 紫色横向光束 | 每次出牌至多一次沿光束轨迹的轻量折射 | 不按伤害次数生成；演奏时压缩或降级 |

## 三、蓝卡后续批次

共享结构组件完成后，首批蓝卡使用独立 `MgrBlueCardVfx` 接入，避免继续扩张屏幕 Shader 文件。逐张结果如下：

| 蓝卡 | 实施结果 | 频率边界 |
|---|---|---|
| 孤独宇宙 | 一颗孤星沿疏离轨道绕行并收束 | 只在初次入队播放；重放沿用演奏与星空音符反馈 |
| 舞台预热 | 暖色预热弧与完成时金色舞台释放 | 初次入队和最终兑现各一次 |
| 群青赞歌 | 群青谱线展开并形成轻量护盾弧 | 每次实际结算可播放；同一 Replay 系列只一次 |
| 全能 | 起音为暖红力量弧，尾音为青绿敏捷弧 | 只绘制本次实际成立的分支 |
| 拖延症 | 入队计时盘与兑现药瓶星屑 | 初次入队和最终生成药水各一次 |
| 甜甜圈洞 | 内环随当前演奏牌数量收紧，外环形成护盾 | 每个出牌系列一次 |
| 活动小丑 | 两张卡沿交叉弧线换位并闪现小丑标记 | 只有交换路径实际接受时播放 |

彩虹音阶、宇宙香料、星降之海和电子天使等动画位于共享施放或能力触发文件中，不能仅因卡牌自己的 `OnPlay()` 没有 VFX 调用就判定为无动画。已有专属攻击、屏幕演出、演奏环境、音符生成或能力触发反馈的蓝卡暂不进入首批，避免重复表达同一玩法结果。

## 四、验证清单

- 连续触发极彩色时，局部扭曲不覆盖选牌、卡牌查看或全局 UI。
- 银河灯在 0 个、1 个和大量音符时均能正常结束，真实音符数量与转换前一致。
- 陨星余波获得能量、补满手牌和施加债务的顺序及数值保持不变。
- 「 鳥 」击杀最后一名敌人后，不因新增视觉继续生成音符或延迟战斗结束。
- 立方棱镜手动打出、自动打出和演奏重放时，每次出牌最多生成一次折射层。
- 禁用人物动画时，卡牌一次性特效仍按既有设置定义工作；不得重新启用人物常驻动画。
- v0.107.1 与 v0.111.0 固定引用下 Release 编译均为 0 警告、0 错误。

## 五、实施结果

- 新增 `MgrRegentStructureVfx`，集中管理两种短寿命屏幕 Shader 和两种角色局部代码绘制动画；每个屏幕实例拥有独立 `ShaderMaterial`，父宿主在寿命结束时一并释放。
- 极彩色的局部扭曲插入 `GlobalUi.Overlays` 之前，只改变战场采样，不盖住选牌、卡牌查看与弹窗；每次满足条件的和弦只调用一次。
- 银河灯先对当前音符种类取只读快照并播放 0.24 秒汇聚，随后才调用原有 `RemoveAllNotes()`；移除数量继续决定后续星空音符生成次数，因此 0 个音符时不等待也不生成虚假视觉。
- 陨星余波用 0.18 秒汇聚替换旧横向风线与全屏暗角，能量、补满手牌和债务仍按原顺序串行执行；外扩余波是自动清理的非阻塞尾迹。
- 「 鳥 」的目标预兆和高空路径线绘制在既有鸟影节点与既有 0.62 秒寿命内，不增加任何等待；立方棱镜在每次 `OnPlay()` 中只生成一条从角色到目标群中心的折射带，不按 X 次伤害重复创建。
- 所有新增速度、尺寸、强度和层级参数均集中在 `MgrVisualTuning` 的五个对应参数组中。

## 六、静态验证结果

- `Validate-MgrContent.ps1 -WarningsAsErrors` 通过：94 张有效卡牌、80 张单人奖励牌、35 张蓝卡及 288 个导入 UID 均一致。
- 单版本 Release 编译通过，0 警告、0 错误。
- 完整双版本构建通过：v0.107.1 payload、v0.111.0 payload 与稳定启动器均为 0 警告、0 错误；产物只写入 `.artifacts/MGRMod-cross-version/`，没有部署到游戏目录。
- 待实机核对 Shader 实际编译、目标位置映射、连续极彩色叠加、银河灯 0/1/多音符、陨星余波结算拍，以及立方棱镜手动/演奏重放观感。

## 七、首批蓝卡补充结果

- 新增 `MgrBlueCardVfx` 作为独立、短寿命的代码绘制宿主；不读取或修改玩法状态，不新增任何 `await`，所有节点到时自动释放。
- 七张牌均在现有玩法分支内调用视觉：空效果牌强调初次入队与最终兑现，条件牌只在条件成立时播放，活动小丑只在牌堆交换已经确认可执行时播放。
- 电子天使、彩虹音阶、宇宙香料和星降之海经共享文件复查后确认已有动画，没有因卡牌自己的 `OnPlay()` 缺少 VFX 调用而重复补做。
- 参数集中在 `MgrVisualTuning.BlueCardVfx`；全部动画为角色局部、非阻塞表现，不复制 RegentFX 资源，不改变卡牌数值、费用、牌堆结果、演奏次数或联机协议。
- 内容登记以 warnings-as-errors 校验通过；v0.107.1 与 v0.111.0 固定引用下的 Release 编译均为 0 警告、0 错误。仍需实机覆盖初次入队、普通重放、最终兑现、Replay、无诅咒及三种活动小丑交换路径。
