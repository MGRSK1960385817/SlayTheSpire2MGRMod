## 一、问题与目标

演奏队列当前依靠一组正 Z 值保证卡牌、悬停预览和进出动画可见：

- 队列根节点 `ZIndex = 55`；
- 队列卡牌按顺序使用正 Z；
- 悬停卡牌使用 `ZIndex = 300`；
- 生成牌入队动画使用 `ZIndex = 320`；
- 离队动画使用 `ZIndex = 450`；
- 金枪鱼冲锋终结演出使用 `ZIndex = 420`；
- 悬停命中区域和大图预览位于 `CanvasLayer = 90`。

这些值能解决战斗场景内部的遮挡，却可能让持久战斗视觉越过原版选牌、卡牌查看、地图、药水等界面。此次重构的目标是：

1. 持久演奏队列不再依赖全局正 Z；
2. 队列内部覆盖改由节点树顺序管理；
3. 卡牌悬停、入队、离队和终结演出保持原有视觉顺序；
4. 临时 `NCard` 归还原版对象池前恢复所有层级和父子状态；
5. 原版全屏及弹出界面始终能够遮住或隐藏演奏队列。

## 二、重构前必须保持的行为

- 队列索引 `0` 位于最右侧，并在卡面重叠处覆盖后加入的卡牌。
- 悬停中的小卡应临时位于其他队列卡之上，并显示跟随鼠标的大图预览。
- 生成牌入队只创建表现用卡面，不复制或改变游戏模型。
- 正常出牌入队可以接管原版正在播放的 `NCard`，动画结束后必须安全归还对象池。
- 离队动画仍从队列槽位飞向对应牌堆；无目标牌堆时保持当前淡出行为。
- 金枪鱼冲锋的卡影和撞击效果必须覆盖队列卡，但不能覆盖原版全屏 UI。
- 打开选牌、卡牌查看、遗物查看、地图或 capstone 界面时，队列、命中区域和大图预览必须同时隐藏。

## 三、设计决定

### 3.1 持久队列

队列根节点恢复为默认 `ZIndex = 0`，并与屏幕空间交互宿主一起放入原版 `MessyCardPreviewContainer`。一个只负责坐标的轻量跟随节点每帧将人物画布变换和 `RackOffset` 转换到战斗 UI 父节点的局部空间，因此人物移动、缩放或震动时，队列仍保持原来的相对位置。

这样做比继续把默认 Z 队列留在人物节点下更稳定：人物后续动态加入的光效不会靠树顺序反过来覆盖队列；队列又仍属于原版战斗 UI 分支，不需要正 Z 就能高于战斗人物并低于全屏界面。五线谱、队列卡锚点和持续装饰通过 `AddChild` / `MoveChild` 的树顺序确定前后关系。

### 3.2 队列卡排序

计划集中维护一次树顺序同步：五线谱在最前（最先绘制），卡牌按“后入队的先绘制、最早入队的最后绘制”排列。悬停时只临时把对应卡锚点移到队列末尾；退出悬停或队列刷新时恢复机械顺序。

### 3.3 预览与进出动画

检查原版 `NCombatUi` 后，决定使用其 `MessyCardPreviewContainer` 作为演奏队列的屏幕空间交互宿主。它是原版用于自由定位临时卡面的战斗 UI 容器，不会像 `CardPreviewContainer` 一样自动重排子节点。

- 命中代理、悬停大图和生成牌临时卡面放入该容器下的 MGR 私有 `Control`；
- 私有宿主保持默认 Z，通过加入顺序让临时卡面位于透明命中代理之后；
- 从视口坐标移动到该宿主时显式执行父节点逆变换，不能继续假设私有 `CanvasLayer` 的原点等于视口原点；
- 原版正在出牌的真实 `NCard` 不重新挂载，只在原父节点中移到最后，动画完成后走统一释放函数。

所有临时卡仍通过统一释放函数恢复 `ZIndex`、`ZAsRelative`、`ShowBehindParent`、枢轴和鼠标状态。

### 3.4 终结演出

队列根节点内部拆成固定树顺序：五线谱 → 卡牌宿主 → 终结撞击宿主 → 终结卡影宿主。这样撞击高于普通队列卡、终结卡影又高于撞击，不再需要 `419/420` 两个正 Z。

## 七、音符栏扩展重构

### 7.1 重构前状态

音符栏仍使用以下显式层级：

- 根节点 `RackZIndex = 50`；
- 每个槽位的透明命中区域 `ZIndex = 20`；
- 音符提示框使用绝对 `ZIndex = 4096`；
- 空槽轮廓 `ZIndex = -1`；
- 音符生成/和弦星屑 `ZIndex = -3`。

根节点正 Z 是药水框和全局提示框补丁仍不能撤销的最后一个主要原因。只删除 `50` 会改变星屑、空槽、音符图案和命中区域的内部关系，因此需要与演奏队列一样完整重构。

### 7.2 固定的跨系统优先级

新增共享的 MGR 战斗 UI 宿主，在原版 `NCombatUi.MessyCardPreviewContainer` 内建立两个固定子层，且全部保持默认 Z：

1. `MgrNoteLayer`：所有玩家的音符栏；
2. `MgrPerformanceLayer`：所有玩家的演奏堆、命中代理和临时演奏卡面。

因为演奏层在节点树中永远位于音符层之后，所以二者发生重叠时，演奏堆必然覆盖音符栏。该顺序不依赖音符或演奏机制谁先触发、谁先创建节点，也不需要重新引入正 Z。

### 7.3 音符栏内部顺序

每个槽位改为固定树顺序：音符星屑 → 空槽过渡 → 已填充音符 → 透明命中区域。星屑和空槽无需负 Z，命中区域也无需正 Z。原版 `NHoverTipSet` 留在原版提示框分支，不再由音符代码强制绝对 `4096`。
