# 「 鳥 」特效多边形绘制报错诊断记录

> 状态：实现已修复并通过静态几何检查与双版本编译，尚待实机回归；未标记为已发布。
>
> 记录日期：2026-09-05。

## 一、问题表现

在2026-09-05的实机战斗中，每次创建「 鳥 」的坠落预兆视觉后，Godot都会在该视觉存活期间逐帧输出以下错误：

```text
ERROR: Invalid polygon data, triangulation failed.
   at: canvas_item_add_polygon (servers/rendering/renderer_canvas_cull.cpp:1713)
   C# backtrace (most recent call first):
       [0] void Godot.CanvasItem.DrawPolygon(...)
       [1] void MGRMod.Mechanics.MgrFallingBirdVisual._Draw()
```

这不是一次性的资源导入警告，而是运行时`CanvasItem.DrawPolygon`无法把提交的多边形三角化；当前帧的填充绘制会被拒绝，随后`_Process()`继续请求下一帧重绘并再次报错。

## 二、日志证据

- 日志文件：`C:\Users\19603\AppData\Roaming\SlayTheSpire2\logs\godot.log`。
- 日志中可见的手动出牌位置为第3697、4029、4620行，目标分别为“悔恨”“悔恨”“研削机Mk4”。
- 本次日志共出现152条完全相同的`Invalid polygon data, triangulation failed.`，并有152个调用栈明确落在`MgrFallingBirdVisual._Draw()`；即每条三角化错误都与该视觉的`DrawPolygon`调用一一对应。
- 以三次可见出牌分段，错误数量为38、76、38。视觉寿命固定为0.62秒，约60 FPS时一次实例大约绘制37至38帧；152条错误约等于四个完整视觉实例。比三次手动出牌多出的一组38帧很可能来自卡农形态等自动出牌链，但日志不会把所有自动出牌都输出为普通“playing card”行，此点属于基于数量与当局牌序的推断。
- 报错期间战斗仍继续结算，没有与该调用栈相邻的卡牌模型、牌堆或音符系统异常；当前没有证据表明它导致“黎明前线”临时复制牌进入弃牌堆，二者应作为独立问题处理。

## 三、源码定位

问题入口位于`Scripts/Mechanics/MgrSignatureVfx.cs`中的`MgrFallingBirdVisual`：

- `Lifetime`为0.62秒；`_Process()`在寿命结束前每帧执行`QueueRedraw()`。
- `_Draw()`计算随进度变化的`wingBeat = sin(progress * PI * 5) * 10`。
- 第633至644行向`DrawPolygon`提交一个由8个动态顶点构成的鸟形填充轮廓；同方法内的`DrawArc`、`DrawLine`和`DrawPolyline`不需要对填充面进行三角化，因此调用栈直接指向这组8顶点轮廓。
- 轮廓同时包含左右翼尖、上方中心凹口、下方身体和第二个中心点。当前错误在整段寿命内持续出现，优先怀疑顶点顺序形成自相交/反向折返，或凹多边形在部分乃至全部`wingBeat`取值下出现退化，而不是偶发的一帧浮点误差。

## 四、后续独立任务检查范围

1. 在调用`DrawPolygon`前验证所有坐标均为有限值、顶点数不少于3、相邻点不重复、面积不接近0。
2. 用`Geometry2D.TriangulatePolygon`或等价诊断直接检查这8个顶点在`wingBeat`全范围内能否返回有效索引，并记录失败区间。
3. 检查轮廓边是否自相交、凹口是否反向穿过身体、顺逆时针是否在动态过程中改变；不要只看静态初始帧。
4. 优先考虑把鸟形拆成数个不自相交的凸三角形/四边形（左右翼与身体分别绘制），避免依赖Godot对复杂动态凹多边形的自动三角化。
5. 保留现有0.62秒寿命、落点、描边、预兆圆环和玩法结算时机；本问题属于纯视觉绘制修复，不应改动「 鳥 」的伤害、音符数量或战斗结束逻辑。
6. 实机覆盖手动打出、演奏自动打出和卡农形态复制打出，确认每个实例均正常释放，日志中该错误归零，并观察高频触发时的帧率与日志写入量。
7. 完成后分别使用v0.107.1与v0.111.0固定引用编译；只有实际进入发布包后，才能在总变更记录中为对应修复加`✅`。

## 六、根因与修复结果

旧轮廓依次连接左翼尖、左肩、上方中心凹口、右肩、右翼尖、右下翼根、下方中心点和左下翼根；其中上方中心点为`0.24 × size`，下方中心点反而为`0.18 × size`。两条中心折线在垂直方向发生反转，使整个八边形形成蝴蝶结式自相交，而不是Godot可三角化的简单凹多边形。因此报错覆盖整段寿命，不只发生在某个极端振翅帧。

修复保留原来的左右翼展、`wingBeat`振翅、坠落位置、轻微旋转、颜色和透明度变化，但不再把整个剪影作为单个八边形提交。填充现拆为：左翼凸三角形、中央凸六边形身体、右翼凸三角形；上、下两条轮廓线独立描边。三个填充面的顶点顺序不会随`wingBeat`改变，也没有共享轮廓折返，所以不存在动态自相交。

静态几何扫描覆盖`_effectScale`为0.1、0.25、0.5、1、1.22、2和4，以及每个缩放下从0至1的10001个动画进度采样。旧八边形的70007个样本全部检测到自相交；新方案共检查210021个独立填充面，有限坐标、非退化面积、无自相交、凸性和统一绕序检查均为0失败，最小双倍有向面积仍为5.674872。源码不再存在原8顶点`DrawPolygon`调用。

内容登记warnings-as-errors通过；固定v0.107.1和v0.111.0原版引用下的Release编译均为0警告、0错误。尚需实机覆盖手动打出、演奏自动打出与卡农形态复制出牌，确认鸟影造型、释放时机正常，并以日志中三角化错误由原基线152条降至0作为最终验收；通过前本项保持未发布、待验证状态。

## 六、卡农形态自动出牌与日志可见性补充

后续核对确认，本局「 鳥 」并没有漏记于卡农形态，容易误判的原因是原版普通日志只在手动`PlayCardAction`中输出`Player ... playing card ...`，而`CardCmd.AutoPlay`不经过这条日志语句。两条路径最终都会进入`CardModel.OnPlayWrapper`，且后者无论`isAutoPlay`真假都会调用`CombatManager.Instance.History.CardPlayFinished`，所以卡农使用的`CardPlaysFinished`战斗历史仍会完整记录自动与手动出牌。

本局第二次可见手动出牌位于日志第4029行，其特效在第4030至4293行产生38次三角化错误；下一玩家回合执行第4321至4363行的可见出牌后、敌方第4613行行动之前，第4380至4607行又在没有新的普通`BIRD`出牌日志时产生独立的38次同类错误，并在第4504行结算伤害。这一整组额外视觉与伤害证明卡农已经自动打出「 鳥 」，只是原版没有为自动出牌输出手动出牌格式的INFO行。

另外，最早的第3697行「 鳥 」发生在第4004行卡农形态之前；当时卡农尚未生效，而且该回合最后一张牌是卡农形态本身，因此下一次只取“上一回合最后一张牌”时不应选择这张更早的「 鳥 」。接手视觉报错的独立任务应同时覆盖手动与卡农自动出牌，但不需要为“卡农漏记「 鳥 」”修改玩法代码。
