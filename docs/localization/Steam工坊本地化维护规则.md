# MGR Steam 工坊本地化维护规则

本文件规定 MGR Steam 创意工坊十种语言标题与简介的长期维护方式。游戏内 JSON 本地化仍以 [`本地化翻译总指导.md`](本地化翻译总指导.md) 和对应语言指导为准。

## 一、权威源与文件位置

- 简体中文简介 `MGRWorkshop/descriptions/schinese.txt` 是工坊简介的语义权威源。
- 其余九种简介位于同一目录，必须直接从简体中文翻译，不以英语作为中间源。
- 十种语言标题分别保存于 `MGRWorkshop/titles/<Steam API 语言代码>.txt`；准确对照和当前标题见该目录的 `README.md`。
- 标题为单行纯文本，不使用 BBCode；简介使用 Steam Workshop 支持的 BBCode。
- Steam 标题最多使用 128 个 UTF-8 字节，简介必须低于 8000 个 UTF-8 字节；保存或上传前必须按字节而不是字符数检查。
- 十种语言角色介绍中，“作者曾制作过一代 MGRMod”这一条的 `MGRMod` 文本固定使用 `[url=https://steamcommunity.com/sharedfiles/filedetails/?l=norwegian&id=3024027467]MGRMod[/url]`；只链接该介绍文本，不修改设置名称中的 `MGRMod`。

## 三、非简体中文版本的永久排除项

用户所说的“无需翻译”在本项目中表示：从其他九种语言版本中整项删除，而不是保留简体中文原文。以下内容只允许出现在简体中文简介：

1. B站联系方式；
2. QQ 联系方式；
3. 包含“这句不用翻译”的整行文字；
4. “特别鸣谢”标题及其整个段落。

X、Discord、BUG 反馈方式以及其他普通内容应正常翻译并保留。

## 四、更新日志结构

简介末尾的玩家向更新日志按日期倒序分组，不再使用“重大更新”“BUG 修复”“表现改善”等类型分类。同一日期的所有玩家向改动放在同一个日期标题和列表中。

- 日期统一使用 `YYYY-MM-DD`；
- 日期标题只写日期，不在玩家可见简介中追加“尚未发布／Unreleased”等发布状态；
- 本地待发布与线上已发布状态统一由 `当前工作项.md` 和变更记录勾选管理，不混入十语言玩家文案；
- 每条使用一至两句话概括玩家能够观察到的结果，不复制内部原因分析、类名、哈希或构建细节；
- 同一天内多张卡牌或遗物的单纯费用、数值、稀有度与简单效果调整统一合并为一条“平衡调整”；条目必须列出全部涉及的卡牌或遗物名称，但不逐张说明具体数值或简单改法。只有新增核心机制、足以改变玩法结构的重做或必须特别提示的兼容变化才单列；
- 多项同类卡牌动画、能力反馈或特效调整统一合并为一条“表现改进”；条目必须列出全部涉及的卡牌、遗物或机制名称，但不逐项展开动画细节。除非某项是重大新功能或关键可读性修复，不再单列；
- 尚未完成但已经进入实现或待验证阶段的玩家可见内容也可以纳入当天日志，但应使用“正在改进”“继续调整”等措辞，避免把尚未验证的结果写成已经稳定发布；
- 总变更记录新增玩家向条目后，下一次明确要求更新工坊简介时应同步十种语言的更新日志。

## 五、上传边界

- 普通内容发布默认不修改任何语言的标题和简介。
- 只有作者明确要求更新本地化标题、简介或两者时，才把对应目录交给上传器。
- Steam 工坊后端的实际行为表明：对已有本地化记录只提交简介，可能把同一语言的标题清空。MGR 不再依赖“未提交字段保持不变”的假设。
- MGR 的任何本地化元数据更新都必须同时携带同一种语言的标题和简介；十种语言应整组提交，不再使用只含 `descriptions/` 的临时工作区。
- 元数据发布必须使用不提交内容、预览图、标签、依赖和更新说明的专用模式，避免为了改标题或简介而刷新内容包。
- 上传器返回成功只代表 Steam 接受了请求。发布后还必须按十种 Steam API 语言代码查询线上元数据，确认标题与简介均非空并与本地文件一致。
- 本地文件完成不代表已经发布；只有实际线上提交成功后才能记录为已发布。
