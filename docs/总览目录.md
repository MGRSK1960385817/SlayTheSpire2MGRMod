# MGR 文档总览目录

> 本文件是 `docs/` 的唯一总入口。后续开始任何工作前，必须先完整阅读本文件和 [`当前工作项.md`](当前工作项.md)，再按任务类别阅读对应的权威文档。
>
> 最后整理日期：2026-08-18。

## Agent 自动引导

工作区根目录的 [`AGENTS.md`](../../AGENTS.md) 负责在任务涉及 `mgrmod/` 时转入项目规则；项目根目录的 [`AGENTS.md`](../AGENTS.md) 再把本总览和 [`当前工作项.md`](当前工作项.md) 设为 Codex agent 的强制启动入口。无论 Codex 从 `塔2模组` 还是 `mgrmod` 目录开始，处理 MGR 的新需求、规划、诊断或实现前，都应先阅读这两个文件，再根据下方分类读取相关权威文档。

如果未来调整文档流程，应同时更新工作区路由规则、项目 `AGENTS.md` 与本总览，避免自动执行规则和文档说明产生分叉。

## 二、后续工作的强制文档流程

1. **开始前先读入口。** 每个新任务都必须先读本文件与 [`当前工作项.md`](当前工作项.md)，确认是否已有同类工作、阻塞或共享文件；随后阅读任务所属分类的权威文档。
2. **开始时登记工作项。** 需要代码、资源、数值、文本或构建改动的任务，开始实施前应在 [`当前工作项.md`](当前工作项.md) 新增或更新条目，写明目标、状态、影响范围、验证计划和关联文档。
3. **每个任务都必须留下文档产物。** 后续每个独立任务至少要新增或更新一份 `docs/` 文档；不得只有代码变更而没有文档记录。小改动优先更新现有权威文档和总变更记录，不要为一句话建立孤立文件。
4. **复杂工作建立专项记录。** 涉及跨系统设计、长链路诊断、迁移或较大回归范围时，在 `records/` 新建专项文档，并从当前工作项和总变更记录链接过去。
5. **完成时闭环。** 任务完成后，应写明原因、修复或改善、验证结果和遗留风险；从当前工作项中移除或转入待发布区，并更新 [`MGR错误修复与表现改进记录.md`](records/MGR错误修复与表现改进记录.md)。
6. **发布后打勾。** 只有实际发布的变更，才能在总变更记录标题后添加 `✅`；未发布条目不得提前打勾。发布新版本时应一次核对所有未勾选条目，避免重复上传或漏传发布文本。
7. **移动文件必须修复引用。** 文档改名或分类调整后，要同步更新 README、脚本和其他文档中的路径，并执行链接与维护脚本检查。

## 三、分类与新建规则

- `docs/` 根目录只保留本总览、当前工作项和必要的目录控制文件；不要继续把普通文档堆在根目录。
- 工程结构、兼容、依赖、构建和遥测基础设施放入 `project/`。
- 卡牌、数值、玩法、视觉和特效原则放入 `design/`。
- 翻译、文本风格、术语和分语言指导放入 `localization/`。
- BUG 修复、性能改进、迁移过程和专项实现复盘放入 `records/`。
- 维护脚本、登记表和供脚本读取的数据放入 `tools/`。
- 新文档名称应直接说明主题；专项记录优先使用“主题 + 记录/方案”，不要使用“新建文档”“临时记录”等模糊名称。
- 同一规则只保留一个权威来源，其他文档使用链接引用，避免复制后逐渐失去一致性。

## 四、权威来源与冲突处理

- 实际运行行为以源码和实机验证为准；文档与实现不一致时，任务必须同时修正实现或文档，不能放任分叉。
- 卡牌与遗物的启用状态、名称和摘要以 [`MGR_content_registry.json`](tools/MGR_content_registry.json) 为维护入口。
- 本地化语义以 `MGRMod/localization/zhs/` 为中文权威源，翻译规则以 [`本地化翻译总指导.md`](localization/本地化翻译总指导.md) 和对应语言指导为准。
- 视觉效果的共享参数与用途以 [`MGR视觉与特效登记.md`](design/MGR视觉与特效登记.md) 为准。
- 正在修改但尚未闭环的事项以 [`当前工作项.md`](当前工作项.md) 为准；已经完成或发布的事实以总变更记录和专项记录为准。

## 五、任务结束前的文档检查

- 当前工作项的状态、下一步和验证结果是否已经更新。
- 是否至少新增或更新了一份与本次工作相关的文档。
- 总变更记录是否使用了正确的类型，而不是把所有修改都写成 BUG。
- 新增文件是否放入正确分类，且已从本总览或相关权威文档链接。
- 相对链接、README 路径和脚本路径是否仍然有效。
- 未发布条目是否保持未勾选，已发布条目是否已经添加 `✅`。
