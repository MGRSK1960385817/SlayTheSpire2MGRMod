# MGR 卡牌描述格式规范

本文件是 MGR 模组新增、改名和修改卡牌描述时必须遵循的长期规范。中文文本先按本规范定稿；英文、日文等其他语言以后翻译时沿用同一信息层级与分段，不照搬中文语序。

## 1. 原版文本基准

本规范依据本机《杀戮尖塔 2》当前版本的全部 605 条简体中文原版卡牌描述整理：

- 300 条为单行，271 条为两行，32 条为三行。
- 普通卡牌中仅 1 条达到四行；另有 1 张依靠大量条件模板动态拼接的特殊牌，不作为常规篇幅范例。
- 原版通常让“一项完整动作”占一行。两个动作若有明确先后、不同对象或不同结算时点，就换行。
- 条件与它直接控制的结果通常放在同一行；只有句子过长或结果本身包含多项动作时才继续拆行。
- 中文正文与动态数字之间不加多余空格，例如 `造成{Damage:diff()}点伤害。`
- 牌堆、格挡、力量、易伤等游戏术语使用游戏支持的颜色标签，例如 `[gold]格挡[/gold]`。

原版参考：

```text
造成{Damage:diff()}点伤害。
给予{VulnerablePower:diff()}层[gold]易伤[/gold]。
```

```text
抽{Cards:diff()}张牌。
丢弃1张牌。
```

## 2. 固定信息顺序

一张 MGR 卡的描述按以下顺序排列，空缺层级直接跳过：

1. 身份机制行：`星空`、`演奏`。
2. 主效果：伤害、格挡、抽牌、生成音符等实际结算。
3. 条件或时点效果：`起音：`、`尾音：`、`演奏结束时，`、`若……`。
4. 卡牌关键词行：`固有`、`保留`、`虚无`、`消耗`等。

标准模板：

```text
[color=#b96cff]星空[/color]。[gold]演奏[/gold]{Performance:diff()}。
造成{Damage:diff()}点伤害。
[gold]尾音[/gold]：获得{Block:diff()}点[gold]格挡[/gold]。
保留。消耗。
```

上例表示玩家最终看到的渲染顺序。实现时，`星空`由 MGR 公共显示层添加，`保留/消耗`由原版关键词系统添加；本地化正文只写`演奏`、主效果和条件效果，不能把自动字段再手写一遍。

### 星空与演奏

- `星空`和`演奏`永远位于第一行。
- 同时具备两者时写在同一行：`星空。演奏2。`
- 只具备其一时，该机制独占第一行：`演奏2。`
- 描述自身身份只写`星空`，不写`星空牌`；只写`演奏2`，不写`演奏牌：演奏2`。
- 叙述其他对象时可以使用类别名，例如“最右侧的1张演奏牌演奏+1”。这里不是重复声明本牌身份。
- 星空标识由公共显示层统一着色，单张卡牌文本不得再次手写一份“星空”。

### 其他关键词

- `固有`、`保留`、`虚无`、`消耗`等由 `CanonicalKeywords`、`AddKeyword` 和 `RemoveKeyword` 声明，交给原版渲染器自动放在最后一行。
- 本地化的 `description` 与 `smartDescription` 不再手写这些自动关键词，否则游戏会显示两次。
- `保留`、`虚无`、`消耗`同时存在两个或更多时，由 MGR 公共显示层尽量合并到同一末行，以减少纵向占用；升级前后遵循同一规则。
- 其他多个关键词的最终渲染顺序服从原版关键词系统；不要在单卡文本中另造一套顺序。
- 升级会获得或移除关键词时，只修改代码中的关键词，不使用 `IfUpgraded` 再显示一遍。

## 3. 着重色、关键词与右侧解释

原版把三件事情分开处理，MGR 也必须保持相同分层：

1. `[gold]文字[/gold]` 只负责把正文标成黄色，本身不会生成右侧解释。
2. 卡牌携带的 `CardKeyword` 决定右侧关键词解释；MGR 自定义关键词由 RitsuLib 注册并进入原版 `Keywords` 集合。
3. 充能球、音符等带图像的概念，由 HoverTip 的图标字段显示图片；不能把图片硬塞进卡牌正文。

### MGR 关键词

- `[gold]强音[/gold]`、`[gold]起音[/gold]`、`[gold]尾音[/gold]`、`[gold]演奏[/gold]`、`[gold]和弦[/gold]`和`[gold]基础音符[/gold]`均为正式关键词，出现时必须同时声明对应 HoverTip。
- `[gold]攻击音符[/gold]`、`[gold]技能音符[/gold]`、`[gold]能力音符[/gold]`、`[gold]状态音符[/gold]`、`[gold]诅咒音符[/gold]`、`[color=#b96cff]星空音符[/color]`和`[gold]幽灵音符[/gold]`均有独立说明与图标。
- `基础音符`的右侧图标同时展示攻击、技能、能力、状态和诅咒五种音符，不再选其中一种作代表。
- `星空`是唯一不使用黄色的 MGR 身份关键词，正文始终使用紫色；右侧解释与星空音符图标仍照常显示。
- 同一概念只解释一次。正文写“幽灵音符”后，不再继续写“幽灵音符触发时获得缓冲”，具体效果放在右侧解释中。

### 普通黄色着重

- 牌堆与区域名使用黄色，例如`[gold]抽牌堆[/gold]`、`[gold]弃牌堆[/gold]`、`[gold]手牌[/gold]`。
- 将诅咒加入弃牌堆时，`[gold]诅咒[/gold]`和`[gold]弃牌堆[/gold]`必须同时着重。
- 格挡、力量、敏捷、虚弱、易伤、缓冲等沿用原版黄色写法；是否附带右侧解释由原版 PowerVar、CardKeyword 或显式 HoverTip 决定。

### 能量文本

- 获得能量使用原版格式：`获得{Energy:energyIcons()}。`，不写“获得3点能量”。
- 固定费用写作`1{energyPrefix:energyIcons(1)}`；减少费用写作`耗能减少{Reduction:diff()}{energyPrefix:energyIcons(1)}`。
- 延迟获得或失去能量仍使用能量图标，例如`下个回合少获得{Debt:energyIcons()}。`
- 描述卡牌费用统一使用“耗能”，不混用“费用”“花费”“能量费用”。

## 4. 分行与句法

- 每个独立结算动作各占一行：先造成伤害，再给予易伤，应写成两行。
- 同一动作的数量修饰不拆行，例如“对所有敌人造成7点伤害3次”。
- 条件紧跟结果，例如：`若本回合未触发过和弦，重复一次。`
- `起音：`、`尾音：`后的文字只写额外或被替换的效果，不重复前文主效果。
- `演奏结束时，`只描述结束钩子；不要再次解释演奏规则。
- 避免无信息量的主语：优先写“获得5点格挡”，不用“本牌使你获得5点格挡”。
- 使用阿拉伯数字；中文量词紧跟数字，不在动态变量两侧加入空格。
- 每个完整句子使用全角句号`。`；标签和动态变量不改变标点规则。

## 5. 动态数字与升级文本

- 数字变量名必须与 C# 中的 `DynamicVar` 键完全一致。例如代码是 `PowerVar<VulnerablePower>`，文本必须使用 `{VulnerablePower:diff()}`，不能简写为 `{Vulnerable:diff()}`。
- 可以由变量表达的升级数值统一使用 `{变量:diff()}`，不要在正文里另写一遍升级说明。
- 只有升级会改写句式或增删实际动作时，才使用 `{IfUpgraded:show:升级文本|基础文本}`；原生关键词的增删由代码负责。
- `description` 表示基础预览，`smartDescription` 负责升级或战斗内条件文本；两者的信息顺序必须一致。
- 选择提示只说明玩家正在选择什么，不重复整张卡的效果。

## 6. 去重检查

提交一张新卡或描述改动前逐项确认：

- 是否同时出现了“星空”和“星空牌”？若是，删掉后者。
- 是否在身份行和正文中重复写了演奏次数？若是，只保留身份行。
- 是否既由公共显示层添加星空，或由原版关键词系统添加固有/保留/虚无/消耗，又在正文中重复添加？若是，删除正文中的副本。
- 是否把“固有/保留/虚无/消耗”放到了开头或主效果中间？若是，移动到最后一行。
- 是否存在两个不同名称却指向同一个动态变量，或文本变量名与代码不一致？若是，以代码变量名为准修正。
- 是否只加了黄色标签，却忘记为 MGR 机制声明右侧关键词？若是，补充关键词声明。
- 是否写了“获得3点能量”或“费用减少2点”？若是，改用原版能量图标格式与“耗能”措辞。
- 删除任意一句后，如果规则与结算仍完整可知，该句通常是冗余句，应删除。

## 7. 实施约定

- 每次新增或修改卡牌时，代码、中文 `description`、中文 `smartDescription` 和 `docs/MGR_content_registry.json` 必须一起检查。
- 暂时停用的卡牌设为 `status: 0` 并取消游戏注册；不再为其维护活动图片。
- 本规范只约束卡牌文字与显示顺序，不得借格式调整改动演奏队列的战斗内位置、动画、悬停或结算链路。
