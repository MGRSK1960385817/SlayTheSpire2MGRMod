# MGR 视觉与特效登记

本文档用于管理两件事：

1. 《杀戮尖塔 2》原版或当前工程能够实现的卡牌特效备选方案。
2. 当前 MGR 卡牌已经使用的特效、颜色、播放方式与演奏适配情况。

修改卡牌特效后应同步更新本文档。实现细节主要位于：

- `Scripts/Mechanics/MgrAttackVfx.cs`：原版特效实例化、着色、缩放与短前摇。
- `Scripts/Mechanics/MgrGunshotVfx.cs`：代码绘制的枪口闪光、弹道和命中闪光。
- `Scripts/Mechanics/MgrFishVfx.cs`：使用 `images/vfx/fish.png` 制作的金枪鱼冲锋虚影与彩色拖影。
- `Scripts/Mechanics/MgrAbilityVfx.cs`：金卡技能/能力的非阻塞施放脉冲、祭品式血液冲击、八十八键蓝色音符群。
- `Scripts/Characters/MgrCharacterAuraVisual.cs`：卫星少女可触发状态下的持续轨道星。
- `Scripts/Mechanics/MgrVisualTuning.cs`：演奏触发速度和演奏期间特效等待倍率。
- `Scripts/Cards/*.cs`：每张卡自己的播放顺序、颜色与是否只播放一次。

### 核心调参入口

常规布局、透明度、速度与缩放优先修改 `Scripts/Mechanics/MgrVisualTuning.cs`，不要直接改状态层：

| 目标 | 主要参数组 |
|---|---|
| 音符排位置、尺寸、间距 | `Notes.RackOffset`、`ArtworkFillRatio`、`DesiredSlotSpacing`、`MaximumRackWidth` |
| 音符数值位置与发光 | `Notes.AmountLabelPosition`、`AmountLabelSize`、`ArtworkGlowRadiusRatio`、`ArtworkGlowStrength` |
| 音符生成与和弦速度 | `FirstNoteEntranceSeconds`、`MinimumNoteEntranceSeconds`、`FirstChordHoldSeconds`、`MinimumChordHoldSeconds` |
| 演奏线谱位置与宽度 | `Performances.RackOffset`、`StaffOffset`、`StaffWidth`、`StaffLineAlpha` |
| 演奏牌位置、大小与间距 | `CardOffsetY`、`MiniatureScale`、`UnfilledCardSpacing`、`FilledRack*Width` |
| 演奏次数标记 | `RemainingCounterSize`、`RemainingCounterTopGap`、`RemainingCounterFontSize`、`RemainingCounterColor` |
| 演奏入队和连续触发速度 | `EnterQueueSeconds`、`EntryAnimationAccelerationPerCard`、`SequentialTriggerDurationMultiplierPerCard` |
| 演奏扫线前后摇 | `StaffPlayheadApproachSeconds`、`StaffPlayheadDepartureSeconds` |
| 流星群坠落节奏 | `MeteorShowerVfx` 参数组 |
| 金枪鱼虚影 | `FishVfx` 参数组与 `images/vfx/fish.png` |

涉及鼠标命中、牌堆路由、演奏次数或和弦结算时，应修改对应机制文件，不能用视觉参数补偿逻辑错误。

## 一、使用原则

- 游戏结算始终严格按卡牌顺序执行。伤害、格挡、抽牌、音符、能力和击杀判断不允许并行。
- 可以缩短或取消的是纯视觉前摇与视觉尾迹，不能让下一张牌越过上一张牌的游戏效果。
- 演奏牌、高频牌和多段攻击优先使用“短、轻、一次”的特效。
- `OnlyPlayAnimOnce()` 只合并同一攻击命令的重复动画，不减少实际命中次数。
- 大型导弹、光束、全屏终结等带等待的演出只给少数招牌牌；进入演奏时自动压缩等待。
- 颜色优先采用 MGR 的黄白、紫色、星光和彩色；诅咒相关使用暗紫或黑红。
- 特效大小可以随基础伤害或成长伤害变化，但必须设置上限，避免遮挡战场。

### 2.3 重型与全屏演出（演奏中谨慎）

| 别名 | 接口或资源 | 特点 | 使用限制 |
|---|---|---|---|
| 超级光束 | `NHyperbeamVfx` + impact | 占屏大、强终结感 | 只给真正的终结技，不用于普通演奏牌 |
| 盛大终曲 | `NGrandFinaleVfx` + impact | 明显预演与等待 | 不应在演奏队列中逐张完整播放 |
| 全屏暗角 | `NSmokyVignetteVfx` 等 | 改变整幅画面气氛 | 同一时间只保留一层，避免遮挡选牌 UI |
| 全屏强化 | `NPowerUpVfx` 或角色专属资源 | 适合能力、爆发强化 | 只在关键节点使用，不逐命中生成 |

### 2.4 技能、能力和非攻击动作的备选语言

| 动作 | 推荐表现 | 备注 |
|---|---|---|
| 生成/复制音符 | 使用音符槽自己的生成、缩放与星屑动画 | 不再叠加攻击命中特效 |
| 触发和弦 | 使用每个音符自己的爆发、外发光和同色星屑 | 结算速度由音符系统统一管理 |
| 进入/触发演奏 | 使用线谱扫线、卡牌脉冲、边缘黄白彩光 | 不把卡牌拉回屏幕中央 |
| 强音、力量、敏捷 | 短促的角色周围强化脉冲 | 可参考 `NPowerUpVfx` 的结构并改色 |
| 诅咒净化/转化 | 黑红或暗紫烟雾向音符槽收束 | 卡牌移动动画仍由原版牌堆接口负责 |
| 牌加入手牌 | 参考《刀刃之舞》《如此甚好》的快速生成动画 | 不使用慢速抽牌动画冒充生成 |
| 牌加入弃牌堆 | 参考机器人的 `Gunk Up` | 应让玩家看清生成了哪张牌 |
| 选择/转化手牌 | 原版选择界面与卡牌移动动画 | 粒子层不得盖住选择界面 |

## 四、当前 MGR 技能与能力特效登记

### 4.1 金卡基础施放层

- 所有有效的 MGR 金卡/先古技能牌和能力牌，在真正开始打出时都会生成一组约 `0.62` 秒、无显式等待、自动释放的代码绘制特效。
- 形状按语义区分为乐谱、回声、轱辘、双环、地平线、烙印、棱彩、卫星、眼睛、创造、黎明、故障、银河、陨星、切割、幽灵与共鸣等类型；不是所有牌共用同一张贴图。
- 这层只负责给高稀有度牌建立最低辨识度，不会覆盖已有的选牌、牌堆移动、音符、和弦或演奏动画。
- 金卡攻击牌继续使用第三节登记的敌方命中与招牌攻击特效，不额外叠加角色中心施放环。

## 五、演奏队列的特效加速规则

### 5.1 层级规则

演奏队列和音符栏不使用非零 Z 或独立高 `CanvasLayer`。二者均属于原版 `NCombatUi.MessyCardPreviewContainer` 下的 `MgrCombatPresentationLayers`，根节点通过 `MgrCombatUiFollowAnchor` 跟随人物画布变换。

跨系统顺序固定为：音符栏 → 演奏环境（例如白虎野之女萤火）→ 演奏卡牌。任何创建时机下，演奏堆都必须覆盖音符栏；不得靠重新加入正 Z 实现。

内部绘制顺序固定为：五线谱 → 队列卡牌 → 终结撞击 → 终结卡影。重叠队列卡、悬停置顶和离队置顶只能通过 `MoveChild` 调整树顺序；不得重新加入 `RackZIndex`、悬停 Z、入队/离队 Z 或私有高 CanvasLayer。临时 `NCard` 必须在进入及归还对象池时恢复默认 CanvasItem 排序状态。

共享 `NCard` 对象池还必须保留取出后的防御性复位：原版 `OnReturnedFromPool()` 会恢复位置、旋转、缩放和颜色，但不会恢复 `ZIndex`、`ZAsRelative` 与 `ShowBehindParent`。MGR 动画若临时提高卡牌层级，结束时必须通过 `MgrCardNodePoolSafety.ReleaseTemporaryCard()` 清洗；任意卡牌从池中重新取出时再恢复一次默认排序，避免旧版本、异常中断或其他遗漏路径留下的脏状态进入手牌、选牌网格、奖励或查看界面。该防御只发生在对象池生命周期边界，不能覆盖界面取得卡牌后主动设置的正常层级。

选牌 overlay、capstone、地图、卡牌查看或遗物查看出现时，队列根节点与交互宿主必须同时隐藏。新增界面类型时，应优先补充可见性条件或迁入正确的原版 UI 分支，不能通过继续抬高其他界面的 Z 来相互覆盖。

### 5.2 特效加速

当前方案不让多张牌的游戏效果并行，而是采用“结算串行、视觉尾迹可重叠、前摇按序压缩”：

1. 演奏牌仍通过 `CardCmd.AutoPlay` 一张一张完整结算。
2. 上一张牌的伤害、音符、能力和击杀检查完成后，才开始下一张牌。
3. 枪击、斩击、星光命中、烟雾等没有显式等待的视觉尾迹可以自然留在场上，不阻塞下一张牌。
4. 小型星弹、大型陨星和横向光束的显式视觉等待，在演奏时乘以：

   `PerformanceVfxWaitMultiplier × 当前队列序号动画倍率`

5. 当前参数位于 `MgrVisualTuning.Performances`：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `SequentialTriggerDurationMultiplierPerCard` | `0.90` | 每往后一张演奏牌，队列动画和特效等待均乘以 0.90。 |
| `MinimumSequentialTriggerDurationScale` | `0.60` | 队列动画倍率最低为 60%。 |
| `PerformanceVfxWaitMultiplier` | `0.70` | 带前摇特效在演奏时先压缩到普通等待的 70%。 |
| `MinimumPerformanceVfxWaitSeconds` | `0.05` 秒 | 避免特效快到完全看不见。 |

因此第一张演奏牌的大型前摇约为正常的 70%，后续依次约为 63%、56.7%、51.0%、45.9%，第六张及以后维持 42%，且单次等待不会短于 0.05 秒。手动打出同一张牌仍保留 100% 的正常前摇。

## 六、后续新增或改动特效的检查单

1. 先判断卡牌属于轻型命中、中型招牌还是重型全屏演出。
2. 检查它能否进入演奏、是否多段、是否会被复制或重复触发。
3. 多段攻击尽量使用一次主体演出；不要为每一段创建完整飞弹或全屏前摇。
4. 只有纯视觉等待接入 `GetVisualWaitDuration`，游戏命令本身必须继续 `await`。
5. 确认颜色、缩放上限、音效与卡名/卡图语义一致。
6. 在本文件“当前 MGR 攻击牌特效登记”中更新记录。
7. 执行编译检查，并重点测试：手动打出、单张演奏、多张演奏、致死中断、即时触发演奏。
