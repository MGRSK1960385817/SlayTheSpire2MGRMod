# MGR 视觉与特效登记

本文档用于管理两件事：

1. 《杀戮尖塔 2》原版或当前工程能够实现的卡牌特效备选方案。
2. 当前 MGR 卡牌已经使用的特效、颜色、播放方式与演奏适配情况。

修改卡牌特效后应同步更新本文档。实现细节主要位于：

- `Scripts/Mechanics/MgrAttackVfx.cs`：原版特效实例化、着色、缩放与短前摇。
- `Scripts/Mechanics/MgrGunshotVfx.cs`：代码绘制的枪口闪光、弹道和命中闪光。
- `Scripts/Mechanics/MgrFishVfx.cs`：使用 `images/vfx/fish.png` 制作的金枪鱼冲锋虚影与彩色拖影。
- `Scripts/Mechanics/MgrAbilityVfx.cs`：金卡技能/能力的非阻塞施放脉冲、祭品式血液冲击、八十八键蓝色音符群。
- `Scripts/Mechanics/MgrBlueCardVfx.cs`：首批蓝卡的短促机制语义动画；全部代码绘制、非阻塞并自动释放。
- `Scripts/Mechanics/MgrRegentStructureVfx.cs`：MGR 自主实现的局部棱镜扭曲、汇聚/释放资源转换和两阶段余波。
- `Scripts/Mechanics/MgrHyakkiYagyoVfx.cs`：百鬼夜行伤害前的暗幕/轻微扭曲，以及敌人局部黑色波纹、墨焰与原生火焰组合命中。
- `Scripts/Mechanics/MgrLightSongVfx.cs`：光线歌三个连续选牌步骤共用的角色中心旋转光束；通过视觉租约与选牌生命周期绑定。
- `Scripts/Mechanics/MgrRegulusVfx.cs`：轩辕十四伤害前一次播放的七彩极光曲线汇聚；不按十四段命中重复生成。
- `Scripts/Mechanics/MgrSongOfSirenVfx.cs`：塞壬之歌效果生效前、自画面上方向下方推进的轻量沉没折射。
- `Scripts/Characters/MgrCharacterAuraVisual.cs`：卫星少女可触发状态下的持续轨道星。
- `Scripts/Mechanics/MgrVisualTuning.cs`：演奏触发速度和演奏期间特效等待倍率。
- `Scripts/Cards/*.cs`：每张卡自己的播放顺序、颜色与是否只播放一次。

常规布局、透明度、速度与缩放优先修改 `Scripts/Mechanics/MgrVisualTuning.cs`，不要直接改状态层：

| 演奏线谱位置与宽度 | `Performances.RackOffset`、`StaffOffset`、`StaffWidth`、`StaffLineAlpha` |
| 演奏牌位置、大小与间距 | `CardOffsetY`、`MiniatureScale`、`UnfilledCardSpacing`、`FilledRack*Width` |
| 演奏次数标记 | `RemainingCounterSize`、`RemainingCounterTopGap`、`RemainingCounterFontSize`、`RemainingCounterColor` |
| 演奏入队和连续触发速度 | `EnterQueueSeconds`、`EntryAnimationAccelerationPerCard`、`SequentialTriggerDurationMultiplierPerCard` |

## 一、使用原则

- 游戏结算始终严格按卡牌顺序执行。伤害、格挡、抽牌、音符、能力和击杀判断不允许并行。
- 可以缩短或取消的是纯视觉前摇与视觉尾迹，不能让下一张牌越过上一张牌的游戏效果。
- 演奏牌、高频牌和多段攻击优先使用“短、轻、一次”的特效。
- `OnlyPlayAnimOnce()` 只合并同一攻击命令的重复动画，不减少实际命中次数。
- 大型导弹、光束、全屏终结等带等待的演出只给少数招牌牌；进入演奏时自动压缩等待。
- 颜色优先采用 MGR 的黄白、紫色、星光和彩色；诅咒相关使用暗紫或黑红。
- 特效大小可以随基础伤害或成长伤害变化，但必须设置上限，避免遮挡战场。

### 1.1 持续与异步特效的实现约束

根据 [`RegentFX v0.5.1 资源与动画参考评估`](../records/RegentFX-v0.5.1资源与动画参考评估.md)，后续新增跨多个状态变化、Tween 或父节点的视觉时遵守以下约束：

- 视觉节点从现有玩法状态派生，不反向充当玩法真值；失去来源卡牌或能力后必须能自行淡出或清理。
- 异步完成回调使用生命周期版本号或等价的所有权检查，过期回调不得清理后来创建的新实例。
- 视觉换父节点时先保存并恢复全局变换，避免角色局部坐标与战斗特效容器坐标不同造成跳动。
- 缓存场景和共享材质视为只读；修改 Shader、粒子尺寸、渐变或随机参数前必须复制实例资源。
- 常驻循环、短促成长闪光和结束爆发应使用独立子层，不能让一次性动画破坏基础循环状态。
- 长条自制攻击场景优先提供 `StartPos`/`EndPos` 标记，由统一适配器完成旋转、缩放和镜像；现有原版 VFX 与代码绘制枪线不为此重构。
- 数百张独立 PNG 的长逐帧演出只可用于极少数招牌牌，不进入普通演奏牌或常驻人物特效；优先使用代码绘制、粒子、Shader、图集或短序列。

### 2.3 重型与全屏演出（演奏中谨慎）

| 别名 | 接口或资源 | 特点 | 使用限制 |
|---|---|---|---|
| 超级光束 | `NHyperbeamVfx` + impact | 占屏大、强终结感 | 只给真正的终结技，不用于普通演奏牌 |
| 盛大终曲 | `NGrandFinaleVfx` + impact | 明显预演与等待 | 不应在演奏队列中逐张完整播放 |
| 全屏暗角 | `NSmokyVignetteVfx` 等 | 改变整幅画面气氛 | 同一时间只保留一层，避免遮挡选牌 UI |
| 全屏强化 | `NPowerUpVfx` 或角色专属资源 | 适合能力、爆发强化 | 只在关键节点使用，不逐命中生成 |

### 2.4 技能、能力和非攻击动作的备选语言

| 动作 | 推荐表现 | 备注 |
|---|---|---|
| 生成/复制音符 | 使用音符槽自己的生成、缩放与星屑动画 | 不再叠加攻击命中特效 |
| 触发和弦 | 使用每个音符自己的爆发、外发光和同色星屑 | 结算速度由音符系统统一管理 |
| 进入/触发演奏 | 使用线谱扫线、卡牌脉冲、边缘黄白彩光 | 不把卡牌拉回屏幕中央 |
| 强音、力量、敏捷 | 短促的角色周围强化脉冲 | 可参考 `NPowerUpVfx` 的结构并改色 |
| 诅咒净化/转化 | 黑红或暗紫烟雾向音符槽收束 | 卡牌移动动画仍由原版牌堆接口负责 |
| 牌加入手牌 | 参考《刀刃之舞》《如此甚好》的快速生成动画 | 不使用慢速抽牌动画冒充生成 |
| 牌加入弃牌堆 | 参考机器人的 `Gunk Up` | 应让玩家看清生成了哪张牌 |
| 选择/转化手牌 | 原版选择界面与卡牌移动动画 | 粒子层不得盖住选择界面 |

## 三、当前 MGR 攻击牌特效登记

“演奏适配”分为：

- **轻量**：没有额外显式等待，适合连续演奏。
- **压缩等待**：正常手动打出保留完整前摇；从演奏堆打出时按队列序号自动加速。
- **一次主体**：多段伤害完整结算，但一整次出牌只播放一次主体动画。

## 五、演奏队列的特效加速规则

### 5.1 层级规则

演奏队列和音符栏不使用非零 Z 或独立高 `CanvasLayer`。二者均属于原版 `NCombatUi.MessyCardPreviewContainer` 下的 `MgrCombatPresentationLayers`，根节点通过 `MgrCombatUiFollowAnchor` 跟随人物画布变换。

跨系统顺序固定为：音符栏 → 演奏环境（例如白虎野之女萤火）→ 演奏卡牌。任何创建时机下，演奏堆都必须覆盖音符栏；不得靠重新加入正 Z 实现。

内部绘制顺序固定为：五线谱 → 队列卡牌 → 终结撞击 → 终结卡影。重叠队列卡、悬停置顶和离队置顶只能通过 `MoveChild` 调整树顺序；不得重新加入 `RackZIndex`、悬停 Z、入队/离队 Z 或私有高 CanvasLayer。临时 `NCard` 必须在进入及归还对象池时恢复默认 CanvasItem 排序状态。

共享 `NCard` 对象池还必须保留取出后的防御性复位：原版 `OnReturnedFromPool()` 会恢复位置、旋转、缩放和颜色，但不会恢复 `ZIndex`、`ZAsRelative` 与 `ShowBehindParent`。MGR 动画若临时提高卡牌层级，结束时必须通过 `MgrCardNodePoolSafety.ReleaseTemporaryCard()` 清洗；任意卡牌从池中重新取出时再恢复一次默认排序，避免旧版本、异常中断或其他遗漏路径留下的脏状态进入手牌、选牌网格、奖励或查看界面。该防御只发生在对象池生命周期边界，不能覆盖界面取得卡牌后主动设置的正常层级。

选牌 overlay、capstone、地图、卡牌查看或遗物查看出现时，队列根节点与交互宿主必须同时隐藏。新增界面类型时，应优先补充可见性条件或迁入正确的原版 UI 分支，不能通过继续抬高其他界面的 Z 来相互覆盖。

大型演奏队列还必须遵守以下空闲态性能约束，且这些约束只改变展示层何时工作，不改变展示结果：静止的边框和剩余次数计数器不得持续逐帧处理或重绘，只能在显示值改变、触发脉冲或边框强度过渡时唤醒，并在过渡结束后休眠；鼠标代理继续每帧观察目标可见性和画布变换，以保证卡牌移动、缩放、悬停及进出队动画期间的命中框同步，但只有目标变换、代理父级变换或目标矩形实际改变时才重新计算四角坐标；队列视图以条目引用身份字典完成成员查找，同时原有列表仍是机械顺序、绘制顺序和悬停置顶恢复的唯一权威来源。移除条目时必须先让视图同时退出列表和引用字典，再释放节点，避免释放回调重入排序或刷新时重新访问失效视图。任何后续优化都不得跳过触发动画、卡面刷新、鼠标命中或队列排序。

上述优化属于所有演奏牌共享的队列基础设施，不是“点滴奇迹”的专用规则。玩家以大量“点滴奇迹”复现低帧率只能说明大型队列路径值得检查，不能据此推断该牌比同数量的其他演奏牌额外昂贵。

### 5.2 特效加速

当前方案不让多张牌的游戏效果并行，而是采用“结算串行、视觉尾迹可重叠、前摇按序压缩”：

1. 演奏牌仍通过 `CardCmd.AutoPlay` 一张一张完整结算。
2. 上一张牌的伤害、音符、能力和击杀检查完成后，才开始下一张牌。
3. 一旦原版 `CombatManager.IsOverOrEnding` 判定战斗进入结束流程，未开始的音符生成、当前和弦剩余音符效果、联机分享和后续重复和弦全部停止；音符钩子不得自行再次遍历全局战斗结束投票。实验体前两次临时死亡完整保留原版复活保护；第三形态死亡且当前动作不是 `RESPAWN_MOVE` 时必须进入收尾。
4. 枪击、斩击、星光命中、烟雾等没有显式等待的视觉尾迹可以自然留在场上，不阻塞下一张牌。
5. 小型星弹、大型陨星和横向光束的显式视觉等待，在演奏时乘以：

   `PerformanceVfxWaitMultiplier × 当前队列序号动画倍率`

演奏牌上方的剩余次数属于玩法状态的预览，但真实计数仍必须等该次`CardCmd.AutoPlay`成功后再提交。触发动画可以先显示本次结算后的预期值；从预减开始到真实提交之间，音符、条件发光或牌面更新引发的通用刷新不得用旧模型值覆盖该预览。提交成功后以真实条目值解锁显示，异常退出则恢复真实值。自延长效果应预览净变化，例如点滴奇迹尾音的“2+1−1”全程显示2；非消耗型立即触发全程保持原值。

6. 当前参数位于 `MgrVisualTuning.Performances`：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `SequentialTriggerDurationMultiplierPerCard` | `0.90` | 每往后一张演奏牌，队列动画和特效等待均乘以 0.90。 |
| `MinimumSequentialTriggerDurationScale` | `0.60` | 队列动画倍率最低为 60%。 |
| `PerformanceVfxWaitMultiplier` | `0.70` | 带前摇特效在演奏时先压缩到普通等待的 70%。 |
| `MinimumPerformanceVfxWaitSeconds` | `0.05` 秒 | 避免特效快到完全看不见。 |

因此第一张演奏牌的大型前摇约为正常的 70%，后续依次约为 63%、56.7%、51.0%、45.9%，第六张及以后维持 42%，且单次等待不会短于 0.05 秒。手动打出同一张牌仍保留 100% 的正常前摇。

普通音符入槽使用独立的分段批次加速曲线：前11个音符沿用原节奏，单回合首个为0.28秒，此后每个减少0.018秒，第11个为0.10秒；从第12个开始每个再减少0.01秒，第18个达到单人最低值0.03秒，后续维持不变。该时长还会继续应用多人`1 / 玩家数`倍率。只缩短入槽视觉等待，不并行或跳过音符状态写入、音效、和弦检测与实际效果。

### 5.3 多人联机统一加速

`MgrVisualTiming` 直接读取原版 `player.RunState.Players.Count`，按 `1 / 玩家数` 计算 MGR 的纯视觉动画与阻塞等待倍率：单人100%、双人50%、三人约33.3%、四人25%。普通视觉等待的单人基准下限0.03秒和演奏大型前摇的单人基准下限0.05秒也按相同玩家数缩放，因此短动画不会在三人或四人房间被固定下限阻止加速。

多人倍率覆盖以下玩家可见链路：

- 音符入槽、和弦清空保持与重复和弦节拍；
- 演奏牌入队、触发、完成、离队、生成牌预览，以及金枪鱼冲锋清空队列的终结演出；
- 已接入 `GetVisualWaitDuration` 的飞弹、光束、全屏前摇与结构化卡牌特效；
- 电子天使、黎明前线、随之任之、八十八键宇宙等专属串行动画；
- 诅咒/手牌生成间隔、自动弃牌预览，以及咔哒咔哒、吉他拨片等短视觉反馈。

加速不进入卡牌模型、RunState保存字段或网络消息，也不修改 `CardCmd.AutoPlay`、伤害、格挡、抽牌、牌堆移动、选牌、随机数、音符效果与击杀检查的等待顺序。房主和客户端都从相同的玩家数量推导本地视觉倍率，因此无需新增联机协议字段；若未来支持超过四名玩家，同一倒数公式也会继续生效。

安全审计约束：任何仅为取得视觉倍率而新增的玩家对象读取都不得成为玩法结算的前置条件。玩家对象意外不可用时，应跳过或恢复原始视觉时长，但伤害、牌堆移动等玩法命令仍必须继续执行。`RunState.Players`会保留曾加入但已掉线的玩家，因此掉线后倍率可能继续按原房间人数计算；这只会让剩余玩家继续使用较快的本地演出，不改变玩法状态或联机协议。

### 5.4 音符与和弦音效设置

模组选项“关闭音符音效”只控制真正生成音符和触发和弦时的 `NoteChannel` / `Chord` 事件，开关默认关闭，玩家手动开启后立即静音；轩辕十四、随之任之等卡牌为自身命中表现复用的同源声音不属于这一机制开关。设置保存在本机全局 MGR 数据中，不进入 RunState 或联机协议，各客户端可独立选择。

MGR Studio Bank 的音效路由为 `bus:/master/sfx`。原版主音量滑条调整 `bus:/master`，音效音量滑条调整 `bus:/master/sfx`，二者都会继续乘到音符与和弦事件上；原版还会分别使用 `slider²` 的线性总线值，因此调用点不得再次手动乘滑条比例，以免重复衰减。

## 六、后续新增或改动特效的检查单

1. 先判断卡牌属于轻型命中、中型招牌还是重型全屏演出。
2. 检查它能否进入演奏、是否多段、是否会被复制或重复触发。
3. 多段攻击尽量使用一次主体演出；不要为每一段创建完整飞弹或全屏前摇。
4. 只有纯视觉等待接入 `GetVisualWaitDuration`，游戏命令本身必须继续 `await`。
5. 确认颜色、缩放上限、音效与卡名/卡图语义一致。
6. 在本文件“当前 MGR 攻击牌特效登记”中更新记录。
7. 执行编译检查，并重点测试：手动打出、单张演奏、多张演奏、致死中断、即时触发演奏。
